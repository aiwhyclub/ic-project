# 구현·PRD 교차 점검 체크리스트

기준 문서: `docs/prd.md` §4·§7, `docs/frd.md` F9·F10, `docs/trd.md`의 위치·저장 정책.

이 문서는 STORY 11.12에서 구현 표면을 직접 점검할 때 사용한다. 체크 표시는 기능이 로컬에서 보이는지 확인했다는 뜻이며, 외부 자격증명·약관 승인이나 사용자 집단 테스트를 대신하지 않는다.

## 9개 화면

- [ ] **01 AI 큐레이션 홈** — 로그인 전 추천 동선 3개, 1~3개 복수 선택, 새 동선 조건 입력
- [ ] **02 지도 동선 계획** — 장소 추가·삭제, 방문 순서·이동수단 변경, 구간별 경로 상태
- [ ] **03 장소 상세** — 운영·예약·주차, 출처·확인일, 현재 코스 추가
- [ ] **04 OAuth 로그인** — Google·Kakao 선택, PKCE 콜백 상태, 취소·실패 후 원래 작업 복귀
- [ ] **05 마이페이지** — 본인 일정 목록, 수정·삭제, 계정·저장정보 삭제 영향 확인
- [ ] **06 저장 동선·여행** — 장소 순서 우선 복원, 최신 경로 재계산, 여행 시작과 플랜B 진입
- [ ] **07 여행 코스 찾기** — 키워드·대상·이동수단·소요시간·관심사 필터와 정렬
- [ ] **08 지도 보기** — Kakao Map 마커와 동등한 장소 목록, 현재 영역 재검색, 상세·새 동선 연결
- [ ] **09 현장 플랜B** — 위치 목적 안내와 수동 fallback, 막힌 이유, 정확히 3개 추천, 한 곳 교체·저장

## Plan B 필수 동작

- [ ] 위치 요청 전 쓰임·저장 여부를 읽고 명시적으로 눌러야 브라우저 위치 권한을 요청한다.
- [ ] 위치 좌표는 지역을 정하는 동안 컴포넌트 상태에서만 사용하고, 지역 결정 뒤 폐기한다.
- [ ] 위치 거부·실패에도 이천 권역 또는 일정의 현재 장소를 직접 선택할 수 있다.
- [ ] 휴관·예약 불가·비·장날·시간 부족 중 하나 이상을 선택할 수 있다.
- [ ] 조건에 맞는 대체 카드가 항상 정확히 3개이고, 추천 이유·이동시간·이동법·운영시간·주의 조건을 비교한다.
- [ ] 카드마다 기본 검증정보·확인일과 실시간 확인 또는 실시간 실패 상태를 구분한다.
- [ ] 기존 일정의 한 정류장만 교체하며 나머지 장소와 방문 순서를 보존한다.
- [ ] 교체 위치 이후 구간을 다시 계산하고, 실패해도 기존 일정과 경로를 잃지 않는다.
- [ ] 추천·경로·실시간·저장 실패를 각각 구분하고 해당 작업의 재시도 또는 기본정보 전환을 제공한다.
- [ ] shared provider가 연결된 경우 replacement 저장·다음 방문 저장을 provider 함수로 전달한다.
- [ ] 교체로 빠진 장소를 `다음에 가기`로 보관할 수 있다. (선택 STORY 12.4)

## 사용자 성공 기준

- [ ] **여행 전:** 대중교통 친구·연인과 자가용 가족 각 5명 중 4명 이상이 로그인 전에 추천 3개를 확인하고, 1~3개 선택·편집 후 OAuth 저장을 완료한다. 마이페이지 카드 수는 선택 수와 같고, 재열기 시 장소 순서와 최신 경로를 확인한다.
- [ ] **현장:** 각 집단 5명 중 4명 이상이 대표 실패 상황에서 60초 안에 플랜B를 선택하고, 재계산된 일정과 기본 검증정보·실시간 상태를 이해한다.
