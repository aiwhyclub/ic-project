## 2. 최신 PRD 기준 제품 흐름

1. 로그인하지 않은 사용자가 AI 큐레이션 홈에서 이천 동선 3개를 확인합니다.
2. 추천 동선 하나를 선택하거나 같은 화면에서 새 동선 만들기를 시작합니다.
3. Kakao Map에서 장소·순서·이동수단을 편집하고 경로 장애 시 외부 Kakao Map으로 전환합니다.
4. 장소 카드나 마커에서 빠른 정보를 보고 필요하면 독립 장소 상세 화면을 엽니다.
5. 저장 버튼 또는 마이페이지를 선택했을 때만 Supabase Google·Kakao OAuth를 요청합니다.
6. 인증이 완료되면 지도 원문 없이 내부 장소 ID, 방문 순서, 이동수단, 체류시간 등 계획정보만 저장합니다.
7. 저장 동선을 다시 열면 장소 순서를 먼저 복원하고 Kakao Map 화면에서 현재 승인된 경로 서비스로 경로·거리·이동시간을 재계산합니다.
8. 공개 Navigation에서 여행 코스 찾기와 지도 보기를 열어 큐레이션 또는 검증된 장소를 탐색하고 기존 계획 흐름으로 연결합니다.
9. 2차에서는 현장 실패 이유와 위치를 바탕으로 플랜B 3곳을 비교하고 기존 장소를 교체합니다.

### 핵심 실패·복구 상태

- AI 큐레이션 생성이 실패하거나 제한시간을 넘으면 검수된 기본 큐레이션 3개를 즉시 표시합니다.
- 지도·장소·경로 API 장애나 쿼터 초과 시 편집 중인 장소 목록과 방문 순서를 유지합니다.
- 지도 오류에는 실패 사유, 마지막 정상 계산시각, 다시 계산, 필요 시 외부 지도 열기를 제공합니다.
- 일부 구간만 경로가 없으면 해당 구간만 오류로 표시하고 나머지 일정은 유지합니다.
- OAuth 실패·취소 시 편집 중인 동선을 잃지 않고 이전 화면으로 돌아갑니다.
- Supabase 저장 실패 시 재시도할 수 있으며 성공 전에는 저장 완료로 표시하지 않습니다.
- Kakao 계열 경로 실패 시 외부 Kakao Map 전환을 제공하고 편집 중인 장소 순서를 유지합니다.
- 실시간 정보 연결 실패 시 확인일이 있는 기본 검증정보로 전환하고 실패 사실을 표시합니다.
- 위치 권한을 거부하면 이천 권역 또는 현재 장소를 직접 선택하도록 전환합니다.

### GSAP + Three.js 안전 기준

- Three.js 캔버스는 AI 큐레이션 홈 Hero에서만 실행하고 지도 SDK 화면에서는 로드하지 않습니다.

- `prefers-reduced-motion`에서는 회전·시차 이동을 끄고 정적 포스터를 표시합니다.

- Hero가 화면 밖으로 벗어나면 렌더링을 일시 중지합니다.

## 6. 화면별 독립 프롬프트 블록

각 블록은 외부 디자인 도구에 단독으로 붙여넣어도 완결되도록 작성합니다.

### 01. AI 큐레이션 홈

- 목적: 로그인하지 않은 사용자가 AI 큐레이션 동선 3개를 비교하고 하나를 선택하거나 새 동선을 시작합니다.
- 사용자 상태: 비로그인과 로그인 모두 접근 가능
- 공통 스타일: 유약 아이보리 `#F5F1E8`, 먹색 `#171A18`, 청자 녹색 `#1F6A5C`, 옅은 청자 `#D8E9E3`, Pretendard Variable 단일 패밀리(제목 700·핵심 600·본문 400·보조 500), 16~24px 카드 모서리와 얇은 경계선
- 앱 셸: 공개 Navigation과 정책·출처 Footer 사용
- 들어갈 요소: 효용 헤드라인, 새 동선 CTA, GSAP·Three.js 청자 오브젝트, AI 추천 동선 카드 3개, 각 카드의 대상 여행객·이동수단·예상 소요시간·주요 장소·추천 이유, Kakao Map 출처 배지, 새 동선 조건 패널의 출발 위치·여행시간·동행 유형·이동수단·관심사
- 눌렀을 때: 추천 카드는 02 지도 동선 계획 화면으로 이동하고 새 동선은 같은 화면의 조건 입력 패널을 엽니다. 마이페이지는 비로그인일 때 04 OAuth 화면을 엽니다.
- 보강 상태: 새 동선 CTA를 누르면 출발 위치·여행시간·동행 유형·이동수단·관심사를 입력하고, 성격이 다른 후보 동선 3개를 생성해 비교한 뒤 하나를 선택하여 02 화면으로 이동하는 상태를 설계합니다.
- 로딩·오류·빈 상태: AI 생성 중에는 서로 다른 3개 카드 스켈레톤을 표시합니다. 제한시간 초과·실패 시 검수된 기본 큐레이션 3개로 교체하며 첫 화면을 비우지 않습니다.
- 반응형: 모바일은 단일 열 카드 3개, PC는 중요도가 다른 Bento Grid 카드 3개
- 접근성: Three.js 장식은 스크린리더에서 제외하고 카드 전체 클릭 외에 명시적인 동선 보기 버튼을 제공합니다.

## 9. 구현용 디자인 시스템

- 단일 기준 파일: 프로젝트 루트 DESIGN.md
- 배경·본문: 유약 아이보리 #F5F1E8, 먹색 #171A18
- 행동·선택: 청자 녹색 #1F6A5C, 옅은 청자 #D8E9E3
- 글자: Pretendard Variable 단일 패밀리. 큰 제목 Bold 700, 단계명·핵심 항목 SemiBold 600, 본문 설명 Regular 400, 짧은 보조 표기 Medium 500
- 간격: 4px 기반 토큰, 모바일 16px, 태블릿 20px, PC 24px 거터
- 형태: 16·20·24px 모서리, 1px 반투명 경계선, 선택·모달·Hero에만 제한된 깊이
- 핵심 컴포넌트: App Shell, Primary CTA, Curated Route Card, Map Split Pane, Place Information Panel, OAuth Card, Saved Route Card, Plan B Card, Status Banner
- 반응형: 0~767px 모바일, 768~1023px 태블릿, 1024px 이상 PC, 콘텐츠 최대 1440px
- 모션: Hero에만 GSAP·Three.js, 나머지는 120~260ms transform·opacity 전환, reduced motion 정적 대체
- 접근성: WCAG 2.2 AA 목표, 마커와 목록 동등 정보, 드래그 대체 순서 버튼, 모달·바텀시트 포커스 관리
- 이미지: 현재 시안 속 장소 이미지는 generated-placeholder이며 실제 서비스 전 출처·사용권이 확인된 사진으로 교체합니다.

### 구현 시 유지할 QA 메모

- 모바일 큐레이션 카드의 장소 칩은 2~3개만 노출하고 나머지는 더보기로 처리합니다.
- 모바일 지도 바텀시트의 순서·삭제·재시도 버튼은 실제 44px 히트 영역을 확보합니다.
- 플랜B 고정 CTA는 브라우저·시스템 UI와 겹치지 않도록 안전 하단 여백을 확보합니다.
- 장소 상세의 읽을 수 있는 간판·장소 표시는 실제 사진인지 확인하고, 생성 이미지라면 교체 전까지 플레이스홀더로 명시합니다.
