# 이천 세이브포인트 기능정의서
상태: 완료

## ⓪ 범위 요약

- 필수 하위 기능: 84개
- 부가 하위 기능: 4개
- 예상 개발 작업 규모: 매우 큼. 실제 작업은 아래 기능 수에 프로젝트 세팅, 데이터 구축, 외부 API 연동, 접근성, 테스트와 배포 점검이 더해집니다.
- 복잡도를 높이는 요인: 3개 이동수단 경로, OAuth 2종, 사용자별 RLS, 지도 원문을 저장하지 않는 재계산 구조, 2차 플랜B·실시간 정보
- 줄인 범위:
  1. 실시간 정보 반영 선택을 부가로 이동 — 1차에서는 확인일이 있는 기본 검증정보를 사용합니다.
  2. 여행 진행 중 현재·다음 장소 강조를 부가로 이동 — 저장 동선 확인과 여행 시작은 유지합니다.
  3. TMAP 경로의 Kakao 지도 내부 교차 표시를 현재 계획에서 제외 — 기존 외부 Kakao Map 전환을 유지하고 TMAP 재도입은 외부 전환으로만 별도 검토합니다.
- 필수로 유지한 축소 후보: 지도 보기의 ‘현재 지도 영역에서 검색’ — 지도를 움직인 뒤 주변을 다시 찾을 수 있습니다.

> 이대로면 수업 시간과 AI 사용량 모두 부담이 클 수 있습니다. 사용자는 실시간 정보와 여행 강조를 부가 기능으로 유지하고, 2026-09-20에는 서면 승인 전 TMAP 내부 교차 표시를 현재 계획에서 제외하기로 결정했습니다.

## ① 요약

이 서비스는 로그인하지 않은 사용자가 이천 큐레이션 3개, 여행 코스 찾기, 지도 보기를 통해 동선 1~3개를 선택하거나 새로 만들고, 선택한 일정별 Kakao Map에서 장소·순서·이동수단을 편집한 뒤 저장할 때 Google 또는 Kakao OAuth로 로그인하는 서비스입니다. 선택한 일정은 선택 개수만큼 각각 별도 일정으로 저장합니다. 저장 일정은 지도 원문이 아닌 내부 장소 ID와 계획정보만 보관하며, 다시 열 때 최신 경로를 계산합니다. 2차에서는 현장에서 막힌 이유와 위치를 바탕으로 플랜B 3곳을 제안하고 선택한 장소로 일정을 교체합니다.

### 역할과 권한

| 역할 | 가능한 행동 |
| --- | --- |
| 비회원 | 큐레이션·코스·장소 보기, 새 동선 생성, 지도 편집, 장소 상세 확인 |
| 로그인 사용자 | 비회원 행동 전체, 동선 저장·조회·수정·삭제, 여행 시작, 플랜B 변경 저장, 로그아웃·계정 삭제 |
| 서버 운영 권한 | 공개 장소·큐레이션 공급, 외부 API 키 사용, 서버 작업 수행. 브라우저에 `service_role`을 노출하지 않음 |

- F10.4 `[필수]` 외부 API 장애에도 편집 장소·순서 유지 — 진입: 외부 API 오류
- F10.5 `[필수]` 실제 서비스 전 장소 사진 사용권·출처 확인 — 진입: 장소 데이터 등록
- F10.6 `[필수]` 위치정보는 동의 후 일시 사용하고 출발지로 저장하지 않으면 장기 보관하지 않음 — 진입: 위치 사용 요청
- F10.7 `[부가]` 포기한 장소를 다음에 가기로 저장
- F10.8 `[부가]` 완성 코스 링크 공유

## ③ 핵심 기능 대표 시나리오

### S1 큐레이션 선택·편집·저장·재열기

- 시작 조건: 비로그인 사용자가 AI 큐레이션 홈에 접근
- 정상 흐름: 큐레이션 3개 확인 → 1~3개 선택 → 선택 일정별 장소 추가·삭제·순서·이동수단 편집 → 한 번에 저장 요청 → OAuth 로그인 → 선택 개수만큼 별도 계획정보 저장 → 마이페이지에서 각각 다시 열기 → 최신 경로 재계산
- 대표 예외: AI 실패 시 기본 3개, 일부 경로 실패 시 해당 구간만 오류, OAuth 취소 시 편집 복원, 저장 실패 시 재시도
- 완료 기준: 저장된 장소 순서가 유지되고 최신 경로·거리·시간이 다시 표시됨
- 데이터 변화: 사용자 동선과 동선 장소 순서 생성. 지도 타일·폴리라인·공급자 원문은 저장하지 않음
- 사용자가 보는 결과: 마이페이지에 일정 카드가 생기고 다시 연 화면에서 계산 상태와 최신 동선이 보임

### S2 현장 플랜B 교체

- 시작 조건: 로그인 사용자가 저장 동선으로 여행 중이며 특정 장소 이용이 어려움
- 정상 흐름: 플랜B 진입 → 위치 또는 수동 권역 선택 → 막힌 이유 선택 → 대체 3곳 비교 → 1곳 선택 → 이후 구간 재계산 → 저장
- 대표 예외: 위치 거부, 실시간 정보 실패, 일부 경로 실패, 저장 실패
- 완료 기준: 기존 장소 하나가 대체 장소로 바뀌고 나머지 순서가 유지되며 변경 내용이 저장됨
- 데이터 변화: 교체된 내부 장소 ID와 변경된 방문 순서 갱신
- 사용자가 보는 결과: 선택 장소와 새 구간, 정보 상태, 저장 결과가 표시됨

## ⑦ 표준 적용 항목과 이유

- OAuth 상태값·PKCE·콜백 검증: 로그인 요청 위조와 코드 탈취를 막는 보안 표준을 적용합니다.
- Supabase OAuth 공급자 연동: Google·Kakao 인증 콜백과 사용자 식별은 Supabase Auth가 중계하고 애플리케이션 DB는 Supabase Postgres를 사용합니다.
- 세션 만료·갱신: 만료된 인증으로 저장하지 않도록 하고 안전하게 다시 로그인하게 합니다.
- 중복 요청 방지: 저장·삭제·플랜B 교체 버튼을 여러 번 눌러도 같은 데이터가 중복 생성되지 않게 합니다.
- 초안과 확정본 분리: 자동 보호된 임시 변경이 저장 버튼을 누르기 전 확정 일정으로 잘못 표시되지 않게 합니다.
- 서버 입력 검증: 브라우저 검사를 우회한 잘못된 값도 서버에서 거절합니다.
- RLS 기본 거부: 허용 정책이 없는 사용자 데이터 접근은 차단합니다.
- 비밀키 서버 보관: 브라우저 번들·로그·오류문에 키를 노출하지 않습니다.
- 개인정보 최소 수집과 로그 마스킹: 필요한 식별정보만 쓰고 로그에 토큰·현재 위치를 남기지 않습니다.
- 접근 가능한 상태 알림: 로딩·완료·오류를 색상뿐 아니라 문구·아이콘·스크린리더 알림으로 전달합니다.

## ⑧ 입력 검증·오류 표시·권한의 공통 동작 규칙

- 필수 입력은 제출 시 항목 가까이에 구체적인 오류를 표시하고 첫 오류로 포커스를 이동합니다.
- 여행시간·체류시간·날짜는 허용 범위를 벗어나면 저장하지 않습니다.
- 검색 결과가 없으면 조건을 유지한 채 필터 초기화와 재검색을 제공합니다.
- 네트워크 오류가 나도 편집 중인 장소·순서·이동수단은 유지합니다.
- 부분 경로 실패는 전체 일정을 막지 않고 실패 구간에만 표시합니다.
- 저장·삭제·교체가 성공하기 전에는 완료 상태로 표시하지 않습니다.
- 임시 초안 저장 실패는 확정 저장 실패와 구분해 표시하고 현재 화면의 편집 내용은 유지합니다.
- 비회원이 보호 기능에 접근하면 로그인 이유와 복귀 위치를 함께 보존합니다.
- 로그인 사용자는 본인의 동선만 조회·수정·삭제할 수 있습니다.
- 권한 거부는 오류로 몰아붙이지 않고 수동 입력 경로를 제공합니다.
- 파괴적 행동은 영향 범위, 되돌릴 수 없음, 취소와 최종 실행을 명시합니다.

## ⑨ 비개발자가 눈으로 확인 가능한 인수 기준

- 첫 화면에는 로그인 없이 서로 다른 큐레이션 카드 3개가 보입니다.
- AI 오류를 가정해도 빈 화면 대신 기본 큐레이션 3개가 보입니다.
- 여행 코스 찾기에서 필터를 적용하면 적용 조건과 결과 수가 보입니다.
- 지도 보기에서 같은 장소를 마커와 목록 중 어느 쪽으로 선택해도 양쪽이 함께 강조됩니다.
- 새 동선 만들기에서 5개 조건을 입력하고 지도 편집으로 이동할 수 있습니다.
- 장소를 추가·삭제·이동수단 변경하면 경로 계산 상태와 결과가 바뀝니다.
- 경로 한 구간을 실패시켜도 다른 장소와 순서는 그대로 남습니다.
- 비로그인 저장 시 로그인 화면이 열리고 취소해도 편집 내용이 남습니다.
- 로그인 후 선택한 일정 개수와 같은 수의 별도 일정 카드가 마이페이지에 나타나고 본인 계정에서만 열립니다.
- 마이페이지에서 일정을 삭제하면 삭제 성공 즉시 해당 카드가 목록에서 사라지고 새로고침 뒤에도 다시 나타나지 않습니다.
- 로그인 사용자가 편집 후 화면을 벗어났다가 돌아오면 임시 초안을 복구할 수 있고, 저장 버튼을 누른 뒤에만 확정 일정이 바뀝니다.
- 저장 동선을 다시 열면 장소 순서가 먼저 보이고 경로가 새로 계산됩니다.
- 계정 삭제 전 삭제되는 정보와 되돌릴 수 없다는 안내가 보입니다.
- 계정 삭제를 최종 확인하면 즉시 로그아웃되고 해당 계정과 저장 동선을 다시 열 수 없습니다.
- 위치 권한을 거부해도 플랜B에서 이천 권역이나 현재 장소를 직접 고를 수 있습니다.
- 플랜B 장소를 선택하면 기존 장소 한 곳이 교체되고 이후 구간과 저장 결과가 갱신됩니다.
- 장소정보에는 출처와 확인일이 보이며 실시간 실패 시 기본 검증정보라는 안내가 보입니다.
